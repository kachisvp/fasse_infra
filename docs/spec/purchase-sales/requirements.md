# 仕入管理・売上管理 要件定義

## 背景

- フロントエンド: Flutter
- バックエンド: 将来的にSpringBoot(Fargate)で実装予定
- 第一弾はAWS CDKで構築したAPIGateway - Lambda - DynamoDBでWebAPIの受口のみ構築する
- 将来的にFlutter → Fargate(SpringBoot) → Amazon Aurora MySQL Serverlessへ移行する（APIGateway - Lambdaは第一弾限定の暫定構成）

## 目的

飲食店（テーブル会計）を対象に、仕入（仕入先からの仕入伝票）と売上（伝票）を管理する。

## スコープ

- 仕入管理: 仕入先マスタ、品目マスタ、仕入伝票（ヘッダ+明細）のCRUD
- 売上管理: メニューマスタ、売上伝票（ヘッダ+明細）のCRUD
- 消費税管理: 消費税率マスタ（標準/軽減/非課税、期間指定）のCRUD

## ユーザーストーリー

- [ ] 仕入担当者として、仕入伝票をヘッダ+明細で登録したい
- [ ] 店舗スタッフとして、売上伝票を営業日（business_date）を指定して登録したい（深夜営業などで日付をまたぐ取引を正しい営業日に紐付けるため）
- [ ] 管理者として、仕入/売上を日付範囲で一覧確認したい（売上は営業日単位）
- [ ] 管理者として、消費税率（標準/軽減/非課税）を税区分・適用期間を指定して管理したい（将来の税率改定に備えるため）

## 受け入れ条件

- [ ] 仕入伝票の登録・一覧（日付範囲）・詳細・更新・削除ができる
- [ ] 売上伝票の登録・一覧（日付範囲）・詳細・更新・削除ができる
- [ ] マスタ（品目・仕入先・メニュー）のCRUDができる（削除は論理削除、`is_active`を`false`に更新）
- [ ] 消費税率マスタ（標準/軽減/非課税）のCRUDができる（区分ごとに適用期間を持ち、複数区分が同時に有効な状態を表現できる）
- [ ] 品目・メニューマスタは税区分（標準/軽減/非課税）を保持する
- [ ] 仕入/売上明細は登録時点で適用された税率をスナップショットとして保持する（消費税率マスタが後日改定されても過去伝票の税額計算根拠が変わらない）
- [ ] 伝票番号（purchase_no / sales_no）は一意である
- [ ] ヘッダと明細は登録時に整合性が保たれる（片方だけ登録される状態にならない）
- [ ] 伝票更新時、明細は送信された内容で全洗い替えされる（送らなかった明細は削除される）

## スコープ外（第一弾）

- 認証・認可（第一弾は認証なし。第二弾以降は`docs/spec/authentication`の方針に従いJWT認証を導入する）
- 仕入先/メニュー単位の集計・一覧
- 集計・レポーティング機能
- SpringBootへの本実装移行（第一弾はAPIGateway + Lambdaの受口のみ）
